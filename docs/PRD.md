# 369stage — PRD (Product Requirements Document)

> 이 문서는 코드베이스(App.tsx, task.ts, gates.ts, worker/src/index.ts 등)와 커밋 히스토리를 근거로 1차 작성했습니다.
> **⚠️ "확인 필요" 표시가 된 항목은 코드만으로 알 수 없는 제품 판단이라, 작성자가 직접 채우거나 수정해야 합니다.**

## 1. 한 줄 정의

작업을 30% → 60% → 90% 단계로 나누고, 90% 단계의 QA 체크리스트를 전부 통과해야만 완료(100%) 처리할 수 있게 강제하는 **셀프 컨펌(self-confirmation) 태스크 관리 앱**.

## 2. 문제 정의

- 인쇄물·영상·이미지·PPT·웹·SNS·DPP(케어라벨) 등 여러 산출물 포맷을 다루는 실무에서, "다 됐다"고 넘긴 결과물에 오탈자·여백·QR 스캔 오류 같은 QA 누락이 반복적으로 발생한다.
- 일반 To-do 앱은 완료 여부만 관리할 뿐, **완료 직전에 강제로 점검하게 만드는 게이트**가 없다.
- 방향(30%)·구조(60%) 단계에서 결정한 내용이 기록되지 않으면, 90% 최종 검수 시점에 왜 그렇게 만들었는지 맥락이 사라진다.

## 3. 타겟 사용자 — ⚠️ 확인 필요

현재 코드 기준으로는 계정(Google 로그인) 단위로 데이터가 분리되는 **개인용 도구**이며, 팀 공유·역할(권한) 개념은 없다.

- [ ] 1인 프리랜서/디자이너의 개인 작업 관리용인지, 향후 팀(에이전시) 협업 도구로 확장할 계획인지
- [ ] `dpp`(케어라벨) 카테고리처럼 특정 산업(의류/제조 라벨링) QA가 포함된 걸 보면 특정 업무 맥락(사내 디자인팀? 외주 대행?)이 있어 보이는데, 이걸 명시하면 카테고리 우선순위나 문구를 더 정확히 다듬을 수 있음

## 4. 핵심 가치 제안

- **강제 게이트**: 90% 체크리스트를 다 체크하기 전엔 완료로 못 넘어감 (`isStageComplete`, `gates.ts`) — 대충 완료 처리하는 걸 구조적으로 막음
- **카테고리별 실무 체크리스트 자동 생성**: 카테고리 10종(공통/UX·UI/인쇄물/영상/이미지 편집/공유용 시안/PPT/웹/SNS/DPP) 각각에 맞는 QA 항목이 미리 정의돼 있어, 매번 체크리스트를 새로 만들 필요가 없음
- **단계별 디렉션 노트**: 30·60% 단계에서 결정 사항을 기록해두면, 90%에서 왜 이렇게 만들었는지 되짚어볼 수 있음
- **기기 간 동기화(선택)**: Google 로그인 + Cloudflare D1로 여러 기기에서 같은 작업 목록을 볼 수 있음. 원격 미설정 시엔 로그인 없이 로컬에서만 써도 됨

## 5. 핵심 플로우

```
작업 생성 (제목·본문·시작일·목표일·카테고리 선택)
   ↓
30% 방향성 검증 — 디렉션 노트만 기록, 체크리스트 없음
   ↓ (다음 단계로)
60% 구조 검증 — 디렉션 노트만 기록, 체크리스트 없음
   ↓ (다음 단계로)
90% 디테일 검수 — 카테고리별 QA 체크리스트 전체 노출
   ↓ (전 항목 체크 완료 시에만)
완료 (100%) — 이후 읽기 전용
```

- 각 단계 이동은 사용자가 수동으로 "다음 단계로" 버튼을 눌러야 함 (자동 진행 없음)
- 완료된(`status: 'done'`) 작업은 전 필드가 읽기 전용으로 전환

## 6. 범위

### 현재 In Scope
- 개인 계정 단위 태스크 관리 (리스트 뷰 + 캘린더 뷰)
- Google 로그인, 원격 동기화(선택), 로컬 전용 사용(원격 미설정)
- 카테고리 10종 QA 체크리스트 템플릿

### 현재 Out of Scope (미구현)
- 팀/멀티유저 협업 (댓글, 담당자 지정, 권한 분리)
- 알림/리마인더 (이메일, 푸시)
- 리포팅/통계 (완료율 추이, 카테고리별 QA 통과율 등)
- 체크리스트 항목 커스터마이징 UI (현재는 `docs/qa_practical.md` 데이터를 코드로 정의)
- 첨부파일/이미지 업로드

## 7. 성공 기준 — ⚠️ 확인 필요

- [ ] 순수 개인 생산성 도구로서 "매일 쓰는지" 여부만 볼 것인지
